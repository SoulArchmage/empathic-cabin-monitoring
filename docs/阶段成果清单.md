## 5. 未落地的结构性缺口：策略选择

v4 在研究方案中新增"策略选择与生成部分"，要求：

> 依据情绪标签的组合，把用户状态划分为若干典型情形，为每种情形分别设计交互策略（提示词侧重点、回应语气与话术方向、是否主动发起语音安抚、提醒的紧急程度），并把状态与策略的对应关系在配置中集中管理。

> 注：本项目最终确定的感知输入为**情绪三分类滑动窗口**（`emotion` / `confidence` / `window`，与感知系统 `state.json` 一致），不含脑电认知负荷；因此情形维度相应调整为「情绪标签 × 持续时长 × 置信度」。

**现状差距**：`TriggerEvent.kind` 有 3 个取值（negative_emotion / stable / recovered），`severity` 只有 mild / severe，由 [trigger.py](../backend/app/decision/trigger.py) 的阈值推出；`strategy`（呼吸引导/共情复述/环境调节/轻量提问）与 `risk` 由大模型自行返回、再由校验器收敛为枚举值，**不是查表得到**；`config.py` 中只有触发阈值，没有策略表；也缺少"语气""是否主动语音""紧急程度"三个字段。

**建议的落地形态**（第二阶段，新增 `backend/app/decision/strategy.py`）：

| 情形（情绪 × 持续时长 × 置信度） | 策略 | 语气 | 主动语音 | 紧急程度 |
|---|---|---|---|---|
| Negative 占比 ≥0.85，持续 > 6s，置信度 ≥0.70 | 安全出口（转介） | 沉稳、简短、明确 | 是 | 高 |
| Negative 占比 ≥0.5，首次确认 | 呼吸引导 | 温和、放慢、陪伴 | 是 | 中 |
| 单窗口 Negative（未达去抖门槛） | 静默观察 | — | 否 | 低 |
| Neutral | 轻量提问 / 环境调节 | 轻快、不打扰 | 否 | 低 |
| Positive | 共情复述（正向强化） | 温暖、确认状态 | 否 | 低 |
| 恢复（连续 2 个窗口低于阈值） | 共情复述（收尾确认） | 温暖、确认状态 | 是 | 低 |

对应改造：`build_messages` 从策略表取"提示词侧重点 + 语气 + 是否主动语音 + 紧急程度"注入，而非仅传 `severity`；矩阵作为配置项集中维护，并补一条覆盖全部组合的用例。
